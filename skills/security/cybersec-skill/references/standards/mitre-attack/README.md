## Purpose in this skill

ATT&CK is a **taxonomy of adversary behaviour**, not a control catalogue. This skill uses it to:

1. **Threat-model** a system: which tactics and techniques an adversary could chain against it.
2. **Tag findings** whose exploitation matches a technique (e.g. a confirmed injection in an internet-facing service is `T1190 Exploit Public-Facing Application`), so findings speak the same language as detection and threat intelligence teams.
3. **Reach defences**: each technique lists its ATT&CK mitigations (`M####`) and detection strategies (`DET####`); D3FEND (`../mitre-d3fend.md`) gives countermeasures; the verifiable control comes from ASVS, SSDF, 800-53 or CSF 2.0.

## Reading rules

- A technique can serve **several tactics**; a sub-technique `T####.###` specialises its parent and is read with it.
- `Platforms` bounds where the technique applies. No matching platform means **NOT APPLICABLE**.
- An ATT&CK mitigation is a **direction of defence**, not a compliance criterion. PASS / FAIL rests on the control of the matching standard.
- ATT&CK carries **no severity**. A technique tag never sets a finding's severity.
- Cite with the version: `T1190 (ATT&CK v20.0)`. Revoked or deprecated IDs (list below) must not be cited; use the replacement.
- Enterprise v18+ splits the old Defense Evasion tactic into **Stealth (TA0005)** and **Defense Impairment (TA0112)**.
