### ES Executive Summary

### 4.1 File Basics

- **R150** — Before attempting to collect or examine files, analysts should have a reasonably comprehensive understanding of files and filesystems.

### 4.2 Collecting Files

- **R152** — During data collection, the analyst should make multiple copies of the relevant files or filesystems typically a master copy and a working copy.27  The analyst can then use the working copy without affecting the original files or the master copy.
- **R153** — If evidence may be needed for prosecution or disciplinary actions, the analyst should get a bit stream image of the original media, label the original media, and store it securely as evidence.
- **R154** — All subsequent analysis should be performed using the copied media to ensure that the original media is not modified and that a copy of the original media can always be recreated if necessary.
- **R155** — All steps that were taken to create the image copy should be documented.
- **R156** — Doing so should allow any analyst to produce an exact duplicate of the original media using the same procedures.
- **R157** — Besides the steps that were taken to record the image, the analyst should document supplementary information such as the hard drive model and serial number, media storage capacity, and information about the imaging software or hardware that was used (e.g., name, version number, licensing information).
- **R158** — Software solutions generally consist of a startup diskette, CD, or installed programs that run on a workstation to which the media to be imaged is attached.30  Some software solutions create logical copies 28  The destination medium should be forensically clean before the copy occurs, so that any existing data on the medium is eliminated.
- **R159** — The destination medium should have a larger storage capacity than the data to be copied. 29  Examples of hardware-based disk imaging tools are Image MASSters SOLO Forensics (http://www.ics-iq.com/) and Logicubes Solitaire (http://www.logicube.com/).
