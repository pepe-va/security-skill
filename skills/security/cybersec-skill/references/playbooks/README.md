## What a playbook is — and is not

A playbook is a **practitioner procedure** (when to use, prerequisites, steps, verification) for one task: hunting a technique, triaging a malware sample, hardening a cloud service, responding to an incident. It is **not a standard**: it never decides PASS / FAIL and never sets a finding's severity. Use a playbook to *do* the work; cite the standard to *judge* it. Playbook steps that call tools or scripts describe what an analyst would run; this skill's execution rules (`../audit/README.md`) still apply — no live probing of systems you do not own, no installs, sandboxed local evidence only.

## How to find one

- By domain: `index-by-domain.md`.
- By threat or defence: `index-attack.md` (ATT&CK technique), `index-d3fend.md` (countermeasure), `index-csf.md` (CSF outcome), `index-ai-and-fraud.md` (ATLAS, AI RMF, F3).
- Then open `<name>/playbook.md` and, if needed, its `references/`.

## What was changed or left out

- `SKILL.md` is renamed `playbook.md`; a provenance comment is added at the top. Content is otherwise unchanged.
- `scripts/` is never copied (helper code, partly offensive tooling). Steps that mention a script refer to the upstream repository.
- **37 offensive playbooks** (original subdomain red-teaming, red-team or offensive-security) are indexed but not copied, because this skill is defensive.
- Framework identifiers were written against older releases. `id-verification.md` lists the 2 that do not resolve in the versions incorporated here.
- Not imported: the repository's OWASP Top 10 mapping (it labels 2021 categories as 2025) and its ATT&CK Navigator layer (ATT&CK v14).
